## Общая схема

Layout Tag Finder — настольное приложение для Windows на C++17. Оно читает
небольшие файлы экранных форм, извлекает предполагаемые имена тегов и сохраняет
связи с полными путями в SQLite. Для поиска достаточно БД. Исходные файлы нужны
при повторном сканировании и открытии результата в Проводнике. Сервер не требуется.

В отдельном репозитории перечисленные файлы лежат в корне. В первоначальной
рабочей папке с несколькими проектами они находятся в `tag-finder/`.

| Файл | Назначение |
| --- | --- |
| `main.cpp` | Интерфейс Win32, события, фоновое сканирование, SQLite, поиск, буфер обмена и Проводник. |
| `extract.h` | Платформонезависимое извлечение строк из байтов; используется приложением и тестами. |
| `test.cpp` | Нативные проверки извлечения и поведения SQLite на основе утверждений `assert`. |
| `sqlite3.c`, `sqlite3.h` | Включённая в проект SQLite 3.38.2 и заголовок публичного API. |
| `build.sh` | Кросс-компиляция для Windows x64. |
| `resources.rc` | Связывает ресурс значка с номером `101` и файлом `icon.ico`. |
| `icon.svg` | Редактируемый рисунок листа бумаги с атомами. |
| `icon.ico` | Значок с изображениями 16, 24, 32, 48, 64, 128 и 256 пикселей. |
| `TagFinder.exe` | Готовая программа; также публикуется в Releases. |
| `.gitignore` | Исключает промежуточные объекты, тестовый бинарник, дампы и пользовательские БД. |
| `README.md`, `README.ru.md` | Инструкции пользователя и команды сборки на двух языках. |
| `ARCHITECTURE.md`, `ARCHITECTURE.ru.md` | Описание реализации на двух языках. |
| `DATABASE.md`, `DATABASE.ru.md` | Таблицы, индекс, запросы и сохранение данных на двух языках. |

При запуске создаётся `tags.sqlite3` рядом с EXE. При сборке создаются
`resources.o`, `sqlite3-win.o`, `sqlite3-test.o`, `test-extract`.

## Библиотеки и инструменты

| Компонент | Для чего нужен | Нужна ли отдельная поставка? |
| --- | --- | --- |
| Стандартная библиотека C++17 | Строки, контейнеры, пути, файлы, потоки, атомарные значения, RAII, исключения. | Среда выполнения C++ связывается статически. |
| SQLite 3.38.2 | Встроенное транзакционное хранилище, подготовленные запросы, поиск. | Компилируется из `sqlite3.c`; отдельной DLL и сервера нет. |
| Win32 User32 | Окна, элементы управления, сообщения, меню, Unicode-буфер обмена. | Входит в Windows. |
| Common Controls (`comctl32`) | Табличный список результатов и инициализация общих элементов управления. | Входит в Windows. |
| Windows Shell (`shell32`) | Выбор папки и выделение файла в Проводнике. | Входит в Windows. |
| COM (`ole32`, `uuid`) | Создание `IFileDialog`, управление объектами COM, идентификаторы интерфейсов. | API Windows; `uuid` предоставляет идентификаторы при линковке. |
| GDI (`gdi32`) | Получение стандартного шрифта интерфейса. | Входит в Windows. |
| LLVM MinGW и `windres` | Заголовки/библиотеки Windows, компиляция, линковка, сборка ресурсов. | Только для сборки. |
| Нативный Clang | Компиляция переносимых тестов в Linux/Termux. | Только для тестов. |
| ImageMagick | Преобразование `icon.svg` в многоразмерный ICO. | Только для пересоздания значка; обычная сборка берёт готовый ICO. |

SQLite находится в общественном достоянии, исходные уведомления сохранены.
Сторонний GUI-фреймворк не используется. Системные DLL и службы среды C Windows
по-прежнему нужны: автономность означает отсутствие дополнительных DLL самого
приложения, Python, сервера БД и сетевого подключения.

## Запуск и взаимодействие компонентов

```text
wWinMain
  -> COM, DPI, Common Controls
  -> папка EXE -> tags.sqlite3 -> создание недостающей схемы
  -> восстановление scan_folder и scan_recursive
  -> регистрация окна и значка -> CreateWindow -> proc(WM_CREATE)
  -> цикл сообщений -> горячие клавиши / proc(...)

proc(WM_COMMAND: Scan)
  -> проверка папки -> enabled(false) -> поток scan(root, recursive)
       -> DB + BEGIN IMMEDIATE -> DELETE старых uses (ещё без фиксации)
       -> обход -> extractTags(bytes) -> вставка пар тег/путь
       -> настройки -> COMMIT
       -> сообщение Done -> proc(Done) -> enabled(true), итог

Search / Enter -> search -> SELECT из SQLite -> список результатов
Правая кнопка -> copyMenu -> copyResult -> resultField -> буфер обмена
Ctrl+C -> copyResult для последнего выбранного столбца
Двойной щелчок -> proc(WM_NOTIFY) -> выделение файла в Проводнике
```

## Функции и их связи

### Текст и хранилище (`main.cpp`)

| Функция/тип | Смысл и использование |
| --- | --- |
| `text(HWND)` | Читает весь UTF-16-текст элемента управления: путь папки или поисковый запрос. |
| `utf8(wstring)` | Преобразует UTF-16 в UTF-8 для SQLite: путь БД, запрос, настройки и пути файлов. |
| `wide(string)` | Переводит значения и ошибки SQLite из UTF-8 в строки Win32. |
| `DB::DB()` | Открывает `databasePath`, устанавливает ожидание блокировки до 5 секунд. Вызывается при запуске, поиске и сканировании. |
| `DB::~DB()` | Закрывает принадлежащее объекту соединение, в том числе при раскрутке стека после исключения. |
| `DB::exec(sql)` | Выполняет фиксированный SQL схемы/транзакций; при ошибке выбрасывает исключение. |
| `Statement::Statement(DB&, sql)` | Компилирует SQL в подготовленный запрос для данного соединения. |
| `Statement::~Statement()` | Освобождает запрос до уничтожения соединения. |
| `Statement::bind(index, value)` | Копирует UTF-8-значение в параметр SQL; ввод не становится частью синтаксиса запроса. |
| `Statement::insert()` | Выполняет запись и сбрасывает запрос/параметры для следующей строки. |

### Индексирование и интерфейс (`main.cpp`)

| Функция | Смысл и связи |
| --- | --- |
| `enabled(bool)` | Разрешает/блокирует выбор папки, сканирование и поиск; вызывается перед потоком и при `Done`. |
| `scan(root, recursive)` | Вход фонового потока: обход, извлечение, транзакционная замена индекса/настроек, сообщения о ходе работы. |
| Лямбда `visit` внутри `scan` | Общий обработчик файла: фильтры, ограниченное чтение, `extractTags`, записи в SQLite. |
| `search()` | Читает параметры поиска, выполняет точный/подстрочный запрос, заполняет три столбца, показывает до 5 000 строк. |
| `resultField(row, column)` | Читает полное содержимое ячейки, увеличивая UTF-16-буфер; используется при копировании. |
| `copyResult(command)` | Копирует поле или строку из трёх полей через табуляцию в Unicode-буфер обмена. |
| `copyMenu(location)` | Определяет строку/столбец мышью либо текущий выбор клавиатуры, показывает меню, вызывает `copyResult`. |
| `control(class, title, style, id)` | Создаёт дочерний элемент со стандартным шрифтом при обработке `WM_CREATE`. |
| `proc(hwnd, message, wParam, lParam)` | Процедура окна: создание, размер, команды, список, сообщения потока и завершение. |
| `wWinMain(...)` | Точка входа Windows: службы, БД, настройки, окно, горячие клавиши и цикл сообщений. |

### Извлечение (`extract.h`)

`extractTags(bytes)` возвращает `set<string>` — уникальные кандидаты из одного
файла. Вложенный токенизатор `inspect(units)` общий для байтовых строк и
распознанных участков UTF-16. `flush()` принимает завершённый кандидат, только
если есть латинская буква и нет символа вне ASCII. Остальные разрешённые символы:
цифры, `$`, `_`, `-`, `.`. Другая ASCII-пунктуация и управляющие байты разделяют имена.

Проход UTF-16 проверяет оба порядка байтов и все начальные смещения. Участок
печатных ASCII-символов должен иметь длину не менее трёх кодовых единиц.
`unit(position)` декодирует соседнюю единицу для проверки продолжения с другим
алфавитом. `Run` хранит интервал байтов, символы и признак отклонения.
Перекрывающиеся интерпретации отбрасываются, если одна похожа на смешанный
алфавит. Маска `wide` не даёт повторно принять младшие байты за одиночные буквы.
В конце `inspect` обрабатывает оставшийся байтовый поток.

Эвристика может пропустить допустимое имя рядом с двоичными данными или принять
случайный печатный фрагмент/имя объекта. Закрытые записи формата не разбираются,
распаковка и расшифровка не выполняются. Подробные правила есть в README.

### Тесты (`test.cpp`)

`main()` запускает примеры извлечения, SQL-проверки в памяти и сценарий записи,
копирования, открытия и обновления реальной БД. `append` собирает байтовые
примеры, `exec` выполняет SQL теста, `scalar` читает одно значение, `Cleanup`
удаляет временную папку. SQL-тесты проверяют поведение хранения, а не Windows-
обёртку `DB` или GUI. Утверждения должны быть включены: не добавляйте `-DNDEBUG`.

## Потоки, владение ресурсами и ошибки

- Глобальные значения содержат дескрипторы окон, неизменный путь БД, настройки,
  выбранный столбец и состояние сканирования. `busy` не допускает второй запуск
  и обычное закрытие окна до окончания фоновой работы.
- Поток сканирования получает копии входных данных и собственное соединение
  SQLite. Поиск и обновление элементов выполняются в UI-потоке; ввод поиска
  заблокирован на время сканирования.
- Каждые 25 принятых файлов отправляется `Progress`, счётчик передаётся в
  `WPARAM`. После успеха или перехваченного исключения `Done` передаёт указатель
  на строку; интерфейс принимает владение через `unique_ptr` и освобождает её.
- `Statement` уничтожается раньше `DB`. При исключении до фиксации закрытие
  соединения откатывает замену. Недоступный файл пропускается и учитывается
  в счётчике; ошибка обхода каталога прерывает сканирование.
- Память буфера обмена принадлежит приложению до успешного `SetClipboardData`,
  затем — Windows. Интерфейсы COM диалога/объекта освобождаются после использования.
- Исходные формы только читаются. Обновление — ручное полное сканирование;
  наблюдателя файловой системы, хешей и таблицы инкрементальных изменений нет.

## Сборка и проверка

`build.sh` собирает ресурс `101`, компилирует SQLite как C с поддержкой потоков
и без загрузки расширений, затем линкует C++17 GUI с `-municode`, `-mwindows`,
статическими C++/SQLite и импортными библиотеками Windows. Пути определяются
относительно скрипта. Команды приведены в [README.ru.md](README.ru.md).

Нативные тесты покрывают извлечение, уникальность, запросы, сохранение, перенос,
замену и откат. Сборка и PE-проверки подтверждают компиляцию, x64 GUI-формат
и встроенный значок. Проверка интерфейса, копирования и Проводника требует Windows.
