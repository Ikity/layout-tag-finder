# Layout Tag Finder

[English](README.md) | [Русский](README.ru.md)

**Техническая документация:** [Архитектура и функции](ARCHITECTURE.ru.md) ·
[Схема SQLite](DATABASE.ru.md) · [Architecture and functions](ARCHITECTURE.md) ·

Небольшое приложение с графическим интерфейсом для Windows x64: находит файлы
экранных форм, в которых встречается заданное имя тега.

[Скачать EXE для Windows](https://github.com/Ikity/layout-tag-finder/releases/latest)

## Запуск

Скопируйте **TagFinder.exe** на компьютер с Windows 10/11 x64 и запустите двойным
щелчком. SQLite и среда выполнения C++ включены в EXE. Устанавливать Python или
отдельную систему управления базами данных не требуется.

1. Нажмите **Choose folder...** и выберите папку с файлами экранных форм.
2. Если нужны вложенные папки, оставьте флажок **Include subfolders**.
3. Нажмите **Scan / replace index** и дождитесь сообщения о завершении.
4. Введите имя, например `Me.UPSStatus_BF` или `$Pump-01.Status`, и нажмите
   **Search** либо Enter в поле поиска.
5. Для полного совпадения включите **Exact name**. Иначе ищется подстрока.
   Оба режима не учитывают регистр. `_`, `$`, `-` и `.` — обычные символы,
   а не шаблоны поиска.
6. В результатах показаны тег, имя файла и полный путь. Двойной щелчок выделяет
   файл в Проводнике Windows.

### Копирование полей

Нажмите правой кнопкой на результат и выберите **Copy tag name** (имя тега),
**Copy file name** (имя файла) или **Copy full path** (полный путь).
**Copy clicked field** копирует поле столбца, по которому вы щёлкнули.
Можно также щёлкнуть по ячейке и нажать **Ctrl+C**. **Copy entire row** копирует
все три поля через табуляцию — удобно для вставки в электронную таблицу.
Юникод в именах файлов и специальные символы сохраняются.

При работе с клавиатурой выберите строку стрелками и нажмите **Shift+F10** либо
клавишу меню. Ctrl+C использует последний выбранный мышью столбец; по умолчанию
это имя тега.

Значок листа бумаги с атомами встроен в EXE и отображается в Проводнике, на
панели задач и в окне приложения. Отдельный файл значка для запуска не нужен.

**Сканирование сохраняется автоматически** в `tags.sqlite3` рядом с EXE.
После перезапуска можно сразу искать теги без повторного сканирования.
Последняя успешно просканированная папка и настройка вложенных папок также
сохраняются. Если файлы добавлены, изменены или удалены, нажмите
**Scan / replace index**. Автоматического повторного сканирования нет.

Успешное сканирование **полностью заменяет предыдущий индекс** содержимым
выбранной папки. Чтобы учитывать несколько папок, выберите их общего родителя.
Замена выполняется транзакцией: ошибка обхода каталогов или записи в БД
сохраняет старый индекс. Отдельные недоступные файлы пропускаются и учитываются
в итоговом сообщении. Ошибка доступа к каталогу останавливает сканирование.

## Правила сканирования

- Принимаются любые расширения, в том числе файлы без расширения.
- Файлы больше **1 048 576 байт (1 МиБ)** пропускаются. Ровно этот размер
  допускается. Объём чтения ограничен, даже если файл растёт во время обработки.
- Имя может содержать `A–Z`, `a–z`, `0–9`, `$`, `_`, `-`, `.` и должно включать
  хотя бы одну латинскую букву. Исходный регистр сохраняется.
- Из текстовых и двоичных файлов извлекаются ASCII-совместимые строки. Также
  эвристически распознаются ASCII-строки в UTF-16LE/BE длиной от трёх символов.
- Символ вне ASCII делает весь текущий кандидат недопустимым, чтобы не сохранять
  только его латинские фрагменты. При соседних нелатинских данных UTF-16-фильтр
  действует консервативно. Неизвестные кодировки и произвольные двоичные данные
  нельзя распознать безошибочно без описания формата.
- Другие знаки ASCII, пробельные и управляющие символы разделяют имена.
  Прямоугольники `NUL`, `SOH` и подобные в редакторе обозначают управляющие
  байты. Сканируйте исходные файлы, а не снимки экрана или текстовые дампы
  с буквальными обозначениями этих байтов.
- Пара «тег — полный путь» сохраняется один раз, даже если тег повторяется
  внутри файла. Один тег может относиться к любому числу файлов.
- Пути сохраняются с поддержкой Юникода, включая `$`, `_`, `-`, `.` в именах
  файлов. Ограничение на латинские буквы относится к тегам, а не к путям.
- Символические ссылки, собственная БД и её служебные файлы пропускаются.
- Отображается до 5 000 совпадений; при достижении лимита предлагается уточнить поиск.

Это **индекс читаемых строк**, а не полноценный декодер закрытого формата.
На исходной фотографии видны как похожие на теги строки (`Me.UPSStatus_BF`),
так и имена объектов (`EmbeddedSymbol1`, `AnalogItem1`). В индекс могут попасть
оба вида, а также случайные печатные фрагменты двоичных данных. Сжатые или
зашифрованные имена не извлекаются. Для точной фильтрации по формату нужен
оригинальный файл с подтверждёнными именами тегов.

## База данных

Переносимый комплект приложения:

```text
TagFinder.exe
tags.sqlite3
```

БД создаётся рядом с EXE при первом запуске, независимо от рабочей папки или
ярлыка запуска. Выберите папку с правом записи, например «Документы» или USB-диск.
**Закройте приложение и скопируйте оба файла вместе**, чтобы перенести программу
и индекс на другой компьютер. Отдельные DLL SQLite, сервер и сеть не нужны.
Во время записи возможен временный `tags.sqlite3-journal`; после успешной записи
и обычного завершения достаточно основного файла БД.

**Переход с первой версии:** закройте старую программу и перед первым запуском
новой скопируйте `%LOCALAPPDATA%\LayoutTagFinder\tags.sqlite3` к новому EXE.
Повторное сканирование для поиска не требуется. Первая версия не сохраняла
папку сканирования, поэтому при следующем обновлении её нужно выбрать один раз.

Сохранённые пути указывают на исходные расположения файлов. Поиск работает и
при их недоступности. После перемещения исходных файлов выберите новую папку
и просканируйте её, чтобы обновить пути и открывать результаты в Проводнике.

Схема:

```sql
CREATE TABLE uses (
    tag TEXT NOT NULL,
    path TEXT NOT NULL,
    PRIMARY KEY (tag, path)
);
CREATE INDEX tag_lookup ON uses(tag COLLATE NOCASE);
CREATE TABLE settings (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
```

`uses` хранит пары «тег — полный путь». Один тег может встречаться во многих
файлах, а один файл — содержать много тегов. Составной первичный ключ исключает
повторы одной пары. `tag_lookup` ускоряет точный поиск без учёта регистра.
В `settings` записываются `scan_folder` и `scan_recursive` (`"1"`/`"0"`) последнего
успешного сканирования. Обе таблицы обновляются одной транзакцией.

Примеры, запросы, правила регистра и отката приведены в [DATABASE.ru.md](DATABASE.ru.md).
Перед копированием или удалением БД закройте приложение. Исходные формы открываются
только для чтения.

## Сборка и проверка

`build.sh` использует установленный кросс-компилятор LLVM MinGW:

```sh
bash build.sh
```

Значок встраивается из `icon.ico` через `windres`. Пересоздать ICO с несколькими
разрешениями из SVG можно с помощью ImageMagick:

```sh
magick -background none icon.svg -define icon:auto-resize=256,128,64,48,32,24,16 icon.ico
```

В проект включены `sqlite3.c` и `sqlite3.h` версии SQLite 3.38.2 из
<https://github.com/azadkuh/sqlite-amalgamation>. SQLite находится в общественном
достоянии; уведомления сохранены в исходных файлах.

Переносимые тесты извлечения и работы SQLite собираются обычным Clang:

```sh
clang -O1 -DSQLITE_OMIT_LOAD_EXTENSION -c sqlite3.c -o sqlite3-test.o
clang++ -std=c++17 -Wall -Wextra test.cpp sqlite3-test.o -pthread -lm -o test-extract
./test-extract
```

Проверены имена, похожие на показанные на фотографии, разрешённые символы,
отбрасывание нелатинских UTF-8-кандидатов, UTF-16LE/BE и смешанные алфавиты,
дедупликация, точный поиск без учёта регистра, буквальный поиск подстроки,
откат транзакций, сохранение после перезапуска, перенос БД, восстановление
настроек и замена устаревших данных. Сборка для Windows успешна; PE-заголовки
подтверждают формат GUI-приложения AMD64.
**Интерфейс Windows не запускался в среде Linux/Android. Оригинальный двоичный
файл экранной формы для проверки также не был предоставлен.**
